# Justificativa e Apresentação do Desenvolvimento do Sistema LARA-SCD (Skin Cancer Detection)

## 1. Contextualização e Problema de Pesquisa
O câncer de pele representa uma das neoplasias de maior incidência global, exigindo métodos de diagnóstico rápido e preciso para reduzir a taxa de morbimortalidade associada a casos severos, como o melanoma. O diagnóstico clínico tradicional baseia-se fortemente na inspeção visual das lesões cutâneas e na avaliação histopatológica posterior. No entanto, a acurácia do diagnóstico visual pode variar substancialmente conforme a experiência do profissional. Nesse contexto, a implementação de sistemas computacionais de Suporte à Decisão Clínica (CDSS), impulsionados por Inteligência Artificial (IA) e Visão Computacional, tem se mostrado uma abordagem de alta relevância científica e tecnológica para mitigar falsos negativos e otimizar o fluxo de triagem médica.

## 2. Justificativa
O desenvolvimento do sistema LARA-SCD (Skin Cancer Detection) justifica-se pela necessidade premente de democratizar e refinar o acesso a uma segunda opinião especializada no diagnóstico de lesões de pele. Ao processar imagens dermatológicas e fornecer inferências probabilísticas de malignidade, a plataforma preenche uma lacuna tecnológica importante. O sistema não visa substituir o crivo clínico, mas sim atuar diferencialmente como uma ferramenta ancilar que padroniza avaliações, prioriza casos urgentes na fila de atendimento e fornece suporte baseado em evidências de aprendizado de máquina contínuo para os profissionais de saúde.

## 3. Arquitetura de Software e Integração de APIs
Para atender aos requisitos de alta disponibilidade, segurança de dados clínicos e eficiência computacional, o LARA-SCD foi arquitetado sob um paradigma de microsserviços e comunicação orientada via APIs RESTful. O escopo do sistema é sustentado por duas APIs principais altamente desacopladas:

- **API Principal (Back-end Core em Java/Spring Boot):** Atua como o maestro do ecossistema governamental e clínico. Responsabiliza-se pela forte orquestração das regras de negócio, persistência relacional (banco de dados MySQL), controle de acesso rigoroso de profissionais e o armazenamento estruturado das imagens provindas dos prontuários.
- **API de Inteligência Artificial (Motor Python/FastAPI):** Este microsserviço isola perfeitamente as demandas de processamento tensorial de visão computacional, isentando a API principal de carregar bibliotecas matemáticas pesadas.

**A Mecânica de Integração entre as APIs:** A comunicação ecossistêmica flui através de requisições HTTP (arquitetura cliente-servidor). Assim que um exame de imagem cutânea é adicionado pela interface cliente ao servidor Java, o back-end Core prepara, de forma síncrona, uma requisição estruturada enviando a imagem encapsulada e seus metadados para a API em Python. A API Python captura a requisição, processa a imagem através da rede neural da IA, extrai as características e retorna na mesma via HTTP o `payload` em notação JSON — contendo a classe da lesão diagnosticada e as probabilidades de acerto (confidence level). O Java intercepta o resultado JSON da IA, realiza o log transacional e disponibiliza o veredito prévio de forma inteligível para que os aplicativos de rotina (front-ends) possam consumir. Esta arquitetura descentralizada assegura fácil escalabilidade, permitindo redimensionar apenas a API de GPU (Python) caso a carga preditiva suba exorbitantemente de demanda.

## 4. Metodologia do Modelo de Classificação Preditiva
Sob a ótica de Ciência de Dados, o serviço de inferência diagnóstica adota uma metodologia de classificação hierárquica dividida em duas etapas acopladas (abordagem top-down). Através do emprego de arquiteturas de redes neurais convolucionais (CNNs) estaduais, notadamente a família YOLO (You Only Look Once), a imagem do paciente submetida primeiro passa por uma análise transversal binária para segregação primária: tumor Maligno ou Benigno. 

A depender desta rede discriminadora inicial, o fluxo é direcionado a um segundo estrato de redes multiclasse específicas. Em casos detectados como benignos, busca-se a subclassificação da dermatose (Nevos, etc.). No caso de malignidade diagnóstica, uma rede subsequente identifica a natureza agressiva, tipificando entre Melanoma, Carcinoma Basocelular, etc. Este refinamento proporciona vasta interpretabilidade dos limites da máquina e entrega aos médicos não apenas um rótulo empírico, mas os pesos probabilísticos para o embasamento do parecer profissional.

## 5. Considerações do Fluxo Prático (Human-in-the-loop)
Alinhado às diretrizes métricas e éticas de Tecnologias em Saúde, o LARA-SCD está metodologicamente centrado no conceito de "Human-in-The-Loop". Todo resultado inferido pelo maquinário gerador da API Python retorna ao sistema back-end compondo apenas uma "sugestão diagnóstica preliminar". É mandatoriamente exposto a um especialista humano cadastrado, que revisa a métrica e insere formalmente e perante responsabilidade o "Veredito Médico". Somente após o evento algorítmico da conformação técnica o laudo da lesão adquire estado de fechado e referendado na trilha de auditoria. Dessa maneira, a confiabilidade médica legal mantem-se atrelada à figura do profissional humano capacitado.

## 6. Perspectivas de Evolução Tecnológica e Trabalhos Futuros (Roadmap)
A arquitetura presente no projeto dita um alicerce robusto preparado explicitamente para as seguintes integrações e propósitos evolutivos no ciclo de vida de produto digital (MLOps/Front-end):

- **Treinamento e Calibração Fina dos Modelos Produtivos de IA:** A API Python atualmente serve o esqueleto arquitetural de integração através do motor YOLO. Para o devir metodológico, os processos futuros abrangem ativamente a importação de volumosos _datasets_ de lesões clinicamente anotadas (imagens dermatoscópicas padronizadas), submetendo essas imagens a fluxogramas exaustivos de aprendizado e cálculo de pesos e taxas de erro. Este esforço foca na materialização dos binários neurais propriamente treinados pelas circunstâncias clínicas que vão adentrar o serviço Python com alta eficácia estatística.
- **Interface e Experiência Móvel (Front-End React Native):** Para o consumo da arquitetura back-end (API Java), delineia-se o desenvolvimento de um terminal gráfico e ergonômico focado na usabilidade médica à beira-leito ou ambulatorial. O aplicativo móvel comteplará a biblioteca React Native, garantindo compilação nativa híbrida (iOS e Android), interfaces ricas com integração e operação fluída da câmera do smartphone — reduzindo atritos mecânicos de transferências de arquivos pelo corpo clínico e acelerando a rotina de diagnósticos em loco (Point-of-Care) conectados em tempo real ao serviço preditivo descentralizado em nuvem.
